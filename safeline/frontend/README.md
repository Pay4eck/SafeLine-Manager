# SafeLine user frontend

The modern profile page is built from the exact upstream source represented by
`frontend.lock.json`.  The reviewed SafeLine source changes live in
`patches/0001-safeline-branding.patch`; the generated JavaScript is never edited
by hand.

Rebuild with Node.js 16.20.2 and Yarn 1.22.22:

```text
git -c core.autocrlf=false clone https://github.com/hiddify/hiddify-user-front.git .test-runtime/user-front
git -C .test-runtime/user-front checkout 5dc87f743f233b8fd0ff0c40b9a3ddbbe7c2812a
git -C .test-runtime/user-front apply ../../safeline/frontend/patches/0001-safeline-branding.patch
cd .test-runtime/user-front
yarn install --frozen-lockfile
yarn build
```

Then package the output with `publish_frontend.py`.  The CI job repeats the
whole build and compares every generated byte (with line endings normalized)
to `safeline/static/user-front` and `safeline/templates/new.html`.

The original source commit did not pass `yarn install --frozen-lockfile`
because `moment` was missing from `yarn.lock`.  The reviewed patch adds that
single lock entry.  Upstream's deploy workflow used Node 16 and unpinned global
Yarn followed by plain `yarn`; SafeLine pins both versions and requires the
corrected lockfile.
